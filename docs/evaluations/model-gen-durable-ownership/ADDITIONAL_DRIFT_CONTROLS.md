# Static-artifact and no-artifact drift controls

## Why the earlier comment control is not decisive

The earlier Arm B comment-only edit established exact source identity drift:
`normalizeSqlSource()` normalizes line endings, not comments, so a comment
changes the generated bytes/source hash. It did **not** establish a runtime
behavior failure. It remains a useful source-identity observation but is no
longer treated as the strongest reason to retain model-gen.

## Reproducible semantic control

`evaluation/evaluate-drift-controls.mjs` creates a temporary canonical SQL and
an actual model-gen output, then applies this parameter-preserving source edit:

```sql
and status <> 'deleted'
```

The old/static binding selects a seeded deleted row; freshly compiled canonical
SQL does not. The runner uses PostgreSQL and removes its temporary source files
after the run.

| Arm | Static state after source-only edit | Detection before execution | Runtime result for deleted row |
| --- | --- | --- | --- |
| A — model-gen | committed model-gen module is stale | `model-gen --check`: fail closed | old module still returns the row if the check is skipped |
| B — primitive-only static artifact | application-owned static binding is stale | none | old binding returns the row |
| C — no artifact | none | no freshness lifecycle required | direct compilation excludes the row |

The Arm B row is a controlled static-artifact reconstruction, not a second
Fresh Agent trial: the original Arm B clean room was intentionally cleaned up
after the initial evidence. Its mechanism is the one that the Arm B agent chose
(canonical SQL plus a static compiler-derived module without a check). The
control does not claim the agent's candidate was rerun.

## Parameter-shape control

The same harness then adds `:includeDeleted` to canonical SQL while leaving the
call-site values unchanged.

| Arm | Result |
| --- | --- |
| A | `model-gen --check` is stale/failing before build/test/DB. Its old binding cannot know the new parameter until regeneration. |
| B | no automatic freshness; the old static binding accepts `{ id }` because it still represents the old query. |
| C | fresh direct compilation sees `includeDeleted`; the unchanged call site fails `ASHIBA_MISSING_PARAMETER` before DB execution. |

Thus the binder remains a direct guard after current canonical SQL is compiled.
It cannot detect a parameter that an intentionally stale static artifact has
hidden. Model-gen is a strong guard **conditional on choosing static generated
state**; it is not proof that the generated state must exist.

## Reproduction

With a disposable PostgreSQL URL in `ASHIBA_REFERENCE_DATABASE_URL`:

```powershell
corepack pnpm --filter @ashiba-ts/cli build
node docs/evaluations/model-gen-durable-ownership/evaluation/evaluate-drift-controls.mjs .
```

The observed JSON is recorded in `raw-results.json`.
