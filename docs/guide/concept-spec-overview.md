# Concept Spec Overview

Concept Specs describe stable product concepts, responsibility boundaries, and invariants.

They are human-owned concept harnesses. They are not implementation plans, DDL, SQL, route definitions, or generated test cases.

## Process Map Rules

Process Maps describe how human-owned concepts move through a business process.

Use Process Maps to review whether a workflow preserves concept boundaries and whether DDL, SQL, and tests have enough evidence for the process they support.

Keep Process Maps above physical design. If implementation details are needed, link to implementation review artifacts instead of turning the Process Map into source code documentation.
